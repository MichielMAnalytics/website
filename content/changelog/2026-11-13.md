## Project permissions for Object Storage, Functions, and AI Gateway

[TBD: Merged to neon-cloud main but not on prod yet. Confirm the prod rollout before publishing, and update `content/docs/manage/user-permissions.md` (line 121 still says these products don't fully enforce per-project permissions). Sources: neon-cloud #12061, #13586, #13598, #13798 (merged), #13859 (open, Realtime secret), all by Russ Dias.]

In organizations that use project roles, Object Storage, Neon Functions, and AI Gateway now follow each member's project role:

- **Object Storage:** Downloading objects or creating a presigned download URL requires Editor. Viewers can still list buckets and objects. Creating a public bucket requires Admin.
- **Functions:** Registering or deleting a custom domain requires Admin.
- **Credentials:** Creating, revealing, rotating, or revoking Object Storage and AI Gateway credentials requires Editor. Viewers can see credential metadata only.

Organization API keys, legacy organizations, and personal projects aren't affected. You can also set an optional `expires_at` when you create a credential, from 1 minute to 365 days out, so keys stop working on a date you choose. See [Per-project permissions](/docs/manage/user-permissions#per-project-permissions).
